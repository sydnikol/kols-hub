# Master Feature List – Kol’s Life, Health & Access System

This document defines **every required feature** for a comprehensive, trauma‑informed, disability‑centered life system. It is written so it can be used for:
- App / software development
- Notion / Obsidian / database builds
- Grant proposals
- Care coordination
- Legal & disability documentation
- Emergency & crisis planning

This is a **systems map**, not a vibes list.

---

## 1. Core Design Principles (Non‑Negotiable)
- Trauma‑informed by default (medical + racial + gendered trauma)
- Energy‑based, not time‑based
- Flare‑aware (everything degrades gracefully)
- No moral language (no “lazy,” “noncompliant,” “failed”)
- Consent‑first data sharing
- Redundancy > efficiency (backups save lives)
- Written over verbal
- Calm, low‑stim, non‑punitive UX

---

## 2. Identity & Context Layer
- Name, pronouns, identity notes
- Cultural context (Black, queer, nonbinary, disabled)
- Relationship structure (polyamorous, multiple partners)
- Chosen family mapping
- Language preferences
- Values & boundaries

---

## 3. Health Condition Registry
Each condition includes:
- Diagnosis name
- Type (physical / neuro / psych / autonomic)
- Daily baseline
- Flare symptoms
- Triggers
- Accommodations needed
- Emergency relevance

Conditions tracked:
- hEDS
- POTS
- Chronic pain
- Inflammatory arthritis
- Asthma
- GI dysmotility
- Migraines
- CPTSD
- AuDHD
- Depression / anxiety

---

## 4. Medication & Treatment System
- Master medication list (dose, timing, purpose)
- Weekly meds (methotrexate logic)
- Contraindications (e.g., folic acid timing)
- PRN logic
- Side‑effect tracking
- Refill alerts
- “Did I take this?” confirmation
- Caregiver verification option

## 5. Symptom & Flare Tracking

## 6. Energy (Spoon) Accounting System
